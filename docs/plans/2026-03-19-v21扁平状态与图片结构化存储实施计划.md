# V2.1 扁平状态与图片结构化存储 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将当前 LeRobot v2.1 输出从分散的 `observation.states.*` / `actions.*` 字段和 `observation.frames.*` 二进制列，调整为用户要求的扁平 schema：`observation.state`、顶层 `actions`，以及 `observation.images.*_color` 的 `struct<bytes, path>` 列。

**Architecture:** 保持现有 `raw -> any4 -> any4lerobot -> v2.1 fallback/postprocess` 主链路尽量不变，把定制化需求集中在本项目自己的 v2.1 后处理阶段完成。具体做法是在 `src/data_converter/converters/lerobot_runner.py` 中，对已经生成好的 v2.1 episode parquet 逐个重写 schema：把状态列压平为 16 维向量，并把视频按帧解码为 JPEG 字节后写入图片 struct 列。

**Tech Stack:** Python 3.11、pyarrow、OpenCV (`cv2`)、pytest/unittest、现有 `lerobot_runner.py` 后处理逻辑、用户提供的参考脚本 `E:/Users/dyz/Documents/WXWork/1688858286666779/Cache/File/2026-03/convert_agibot_raw_to_lerobot.py`。

## 范围与前提

- 作用范围仅限 LeRobot `v2.1` 输出。
- 非 `v2.1` 版本、raw 适配主流程、元数据中与本次需求无关的字段，应保持不变。
- `observation.state` 为 16 维 `float32`：左臂 7 维 + 右臂 7 维 + 左抓夹 1 维 + 右抓夹 1 维。
- 顶层 `actions` 也为同样的 16 维 `float32`，按用户要求作为 `observation.state` 的冗余副本保存。
- 图片列固定为：
  - `observation.images.hand_left_color`
  - `observation.images.hand_right_color`
  - `observation.images.head_color`
- 图片列值类型为 `struct<bytes: binary, path: string>`。
- `path` 字段采用稳定的逻辑路径字符串，例如 `images/<camera>/episode_<id>/frame_<index>.jpg`，即使真实文件不单独落盘也保持可追踪。

## 验收清单

- v2.1 parquet 中不再保留分散的 `observation.states.*` 列。
- v2.1 parquet 中不再保留分散的 `actions.*` 列。
- `observation.state` 精确为 16 维。
- 顶层 `actions` 精确为 16 维。
- `actions` 与 `observation.state` 数据一致，满足“冗余一份”的要求。
- 图片列类型为 `struct<bytes, path>`，不是单纯的 binary。
- 图片列命名精确为 `hand_left_color` / `hand_right_color` / `head_color`。
- 非 v2.1 流程不被本次改动影响。

## 实施风险

- 当前上游 any4 仍可能生成旧 feature 声明，必须保证 metadata 与重写后的 parquet 一致。
- `path` 字段没有现成上游约束，执行时要固定规则并用测试锁死。
- 视频帧数与 parquet 行数不一致时不能静默错位写入。
- 现有测试中仍存在对 `observation.frames.*` 的历史断言，更新时要避免误保留旧契约。
