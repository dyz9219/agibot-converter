# GUI 启动 Flet 兼容修复

## 问题背景

用户反馈远程下载的 `DataConverterShell-full.exe` 双击无法打开，截图报错为：

```text
module 'flet.controls.padding' has no attribute 'symmetric'
```

此前验证只覆盖了打包 exe 的 `--internal-run-conversion` 内部转换入口，未覆盖 GUI 双击启动链路，因此对 Windows 包可用性的结论不完整。

## 根因分析

本地开发环境的 Flet 仍支持 `ft.padding.symmetric(...)` / `ft.padding.only(...)` 这类模块级 helper。
远程 Windows full 包中打入的 Flet 版本为 class-based API：`flet.controls.padding` 模块只导出 `Padding` 类，
`symmetric` / `only` 是 `ft.Padding` 的类方法，不再是 `ft.padding` 模块函数。

进一步检查发现 `border` 也存在同类差异：远程包中的 `flet.controls.border` 只导出 `Border` 类，
`all` / `only` 是 `ft.Border` 类方法。若只修复 padding，GUI 启动后仍可能继续在 `ft.border.all(...)`
或 `ft.border.only(...)` 处失败。

## 改动方案

在 `src/data_converter/main.py` 增加兼容 helper：

- `_padding_symmetric(...)`
- `_padding_only(...)`
- `_border_all(...)`
- `_border_only(...)`

这些 helper 优先使用旧版模块级 API；若不存在，则回退到新版 `ft.Padding` / `ft.Border` 类方法。
同时将 GUI 构建路径中的 `ft.padding.symmetric/only` 与 `ft.border.all/only` 调用统一替换为兼容 helper。

## 回归测试

在 `test/python/test_main_entry.py` 中新增两个回归测试，使用 fake Flet 对象模拟远程包中的 class-based API：

- `test_padding_helpers_support_class_based_flet_padding_api`
- `test_border_helpers_support_class_based_flet_border_api`

先验证测试在 helper 不存在时失败，再实现兼容层后转绿。
