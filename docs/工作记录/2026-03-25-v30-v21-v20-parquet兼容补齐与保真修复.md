# 2026-03-25 v3.0 / v2.1 / v2.0 parquet 兼容补齐与保真修复

## 问题背景
用户反馈已确认 `v2.1` 数据可用，但 `v3.0` 输出目录 `data/chunk-000` 下的 parquet 看起来仍然“空”，并要求：
- `v3.0` 的数据格式与转换结果和 `v2.1` 保持一致；
- `v2.0` 也与 `v2.1` 保持一致；
- parquet 转换后不能丢字段、不能少内容。

本轮同时核查了外部真实输出目录：
`D:\下载\windows-x64-agibot-isaac-downloader-真机真机\downloads\转换后\custom_task_pick_the_fruit_20260205181347__lerobot_v30\data\chunk-000ile-000.parquet`

## 现象与根因分析
### 现象
- 外部 `v3.0` parquet 实际并不是 0 行空表，读取后共有 `2422` 行。
- 旧逻辑下：
  - `v3.0` parquet 只有原始状态/动作列与外置视频；
  - `v2.1` 会额外重写成兼容列；
  - `v2.0` 默认没有补齐同一套兼容列。
- 三个版本的 parquet 结构天然不一致，容易被误判为“v3.0 少东西”或“某版本 parquet 不完整”。

### 根因
- `src/data_converter/converters/lerobot_runner.py` 中原本只在 `v2.1`（或显式勾选 embed）时做 parquet 补齐。
- `v2.1` 的 schema rewrite 使用硬编码目标 schema，之前会覆盖掉原列，存在“兼容列出来了，但原始列可能被裁掉”的风险。
- rewrite 里 `actions` 兼容列错误地直接复用了 `state_rows`，存在动作列内容写错的风险。

## 改动方案
### 代码修改
在 `src/data_converter/converters/lerobot_runner.py` 做了以下调整：
- 将 `v3.0 / v2.1 / v2.0` 全部纳入统一 parquet 兼容补齐流程。
- 将原 `v2.1` 硬编码 schema 改为“保留原始列 + 追加兼容列”的方式：
  - 保留 `observation.states.*`、`actions.*` 等原始列；
  - 追加 `observation.state`、`actions`；
  - 追加 `observation.images.hand_left_color / hand_right_color / head_color` 图像结构列。
- 修复 `actions` 兼容列错误复用状态列的问题，改为优先使用 `actions` 或 `actions.joint.position` 真正动作数据。
- 统一更新 `info.json` 的 `features`，保证三种版本都带上同一套兼容列定义。

### 测试修改
更新并扩展了以下测试预期：
- `test/python/test_lerobot_video_embedding.py`
- `test/python/test_lerobot_v21_schema_rewrite.py`
- `test/python/test_lerobot_array_fidelity.py`

重点改为校验：
- 兼容列存在；
- 原始列仍然保留；
- `actions` 与真实动作数组一致，不再错误等于 state。
